# Changelog

## [0.0.1] - 2026-06-04
- Initial release of the Sannel Encoding Manager project.
- Included standard documentation (README, LICENSE, CODE_OF_CONDUCT, SECURITY).
- Multi-angle disc track support: when a disc title has more than one angle, the runner now produces one output file per angle (e.g. `Movie Title - a1.mkv`, `Movie Title - a2.mkv`). Single-angle titles are encoded as before with no suffix. Angle count is parsed automatically from the HandBrake scan JSON (`AngleCount` field).
- MCP server at `/mcp` so AI assistants can browse media roots, scan discs, look up TVDB/OMDb names and queue encode jobs (16 tools). Per-user API keys (hash-only storage, shown once) managed on the new **AI Access** page, which also shows client setup snippets. Forced rescans/refreshes are rate-limited per key.
- Disc menu inspection (`inspect_disc_menus`): an isolated probe maps every DVD/Blu-ray menu button to a submenu or a title/chapter range (libdvdnav exact for DVD, libbluray best-effort for Blu-ray, BD-J with `DiscMenu:JavaHome`) and returns annotated libvlc screenshots. Results are cached in the `DiscMenuCache` table.
- Queue items record who created them and whether via the UI or MCP (`CreatedBy`, `CreatedByObjectId`, `CreatedVia`), shown in the queue detail dialog.
- "Copy for AI" button in the Filesystem Browser copies an item's root, path and suggested MCP steps.
- New `Mcp` and `DiscMenu` configuration sections; `AddMcpSupport` migration for SQLite and PostgreSQL.
- Disc menu fixes from the first real-disc runs: BD-J menus are detected from their graphics overlay (they never raise the HDMV menu event); the JRE's `bin` folders are put on the probe's PATH on Windows so `jvm.dll` loads; Blu-ray and screenshot failures now report the actual reason; DVD screenshots no longer give up when libvlc never reports a menu title; relative `DiscMenu:OutputPath` defaults under `%ProgramData%\SannelEncodingManager` on Windows. Probe version bumped to 2 so cached menu maps are rebuilt.
- Deleting a queue item while a runner is encoding it now stops the runner (its cancel-requested poll returns true for the deleted job) and its remaining status reports are ignored instead of failing with "Queue item was not found".
- BD-J menu timing: wait for the menu's intro animation, longer quiet periods after key presses and Enter, Blu-ray screenshots wait for real picture content instead of the first (black) frame, and unknown buttons report what was observed (playlist before/after, graphics redraws). Probe version 3.
- BD-J: idle events no longer exhaust read-count limits instantly (every wait is now time-based, so the Java menu has time to react to keys); Blu-ray screenshots wait 8s after the picture appears so the menu bar has slid in. Probe version 4.
- Per-button menu screenshots: every menu button gets its own screenshot with that button highlighted (cyan outline) and its focusPath recorded; get_disc_menu_screenshot takes buttonNumber and returns that image plus exactly what the button does. DVD walks the highlight in one session; Blu-ray replays each focus path. The probe stops screenshots before its time limit so the map is always written. Probe version 5.
- Menu screenshots try several libvlc disc addresses (percent-encoded, plain, Windows-native) until one opens, fixing "libvlc stopped before a menu appeared (0 frames)" on Windows (seen on a DVD folder with a space in its name).
- DVD menus reached first through the remote's Root/Title menu key now get an arrow-key + Enter reach path found by searching the menu graph, so their screenshots show the right menu (libvlc cannot send those remote keys; the TMNT Episode Selection screenshot showed the main menu).
- Blu-ray BD-J crawling now works end to end: still-frame and end-of-title events no longer exhaust read limits in milliseconds, Enter returns as soon as the graphics change and settle (no 20s wait per submenu), short transition playlists are followed to the real title, submenus are mapped in the session that opened them, and a submenu's focus walk stays inside the panel that opened instead of wandering back onto the menu bar. Blu-ray per-button screenshots walk the highlight in one session. Probe version 6.
- Blu-ray menu inspection reworked from real-disc testing (Tales from Earthsea BD-J, Naruto Shippuden HDMV), probe version 7:
  - Menus are reached with the Title Menu key in both the crawl and the screenshots (libvlc "set title 0"), so logos and trailers are skipped and both land on the same menu.
  - Reads are paced to real time: HDMV menus run their page/selection timeouts on stream time, which closed submenus mid-crawl when the disc was read at full speed.
  - HDMV graphics decoding fixed (RLE end-of-line markers were not consumed, blanking whole buttons) and highlights drawn by palette changes are detected.
  - Button start chapters are read after the seek to the chapter mark; HDMV highlights get a short settle time.
  - Focus walks detect leaving a panel (closing it, moving onto the menu bar), reopen the menu when lost (closing the old session first — two BD-J sessions in one JVM deadlock), and verify where each route lands (menus that remember their last focus).
  - BD-J screenshots: libvlc cannot blend BD-J graphics ("BGRA -> I420"), so the crawler saves each focus state's graphics plane and the renderer draws it over libvlc's video.
  - The Blu-ray crawl and screenshot rendering each run in a child process; the crawl child saves the map after every step, so if it has to be stopped at its time limit the menus found so far are kept.
  - BD-J focus states are fingerprinted at full resolution (thin focus underlines fell between sampled rows), walks re-route on unknown landings and defer unreachable moves instead of restarting the Java menu, buttons are activated nearest-first, and submenus are mapped after the current menu's own buttons so a submenu walk cannot use up their time. Buttons the crawl did not reach say so.
  - Annotated screenshots put number badges beside buttons so stacked labels stay readable.
  - Defaults raised to `TimeBudgetSeconds` 1350 and `ProbeTimeoutSeconds` 1800 (BD-J discs can take 20+ minutes).
- Interlace detection (plan 008): every disc title and media file gets an interlace verdict (interlaced / telecined / mixed / progressive / pending / unknown) and a recommended preset.
  - DVD titles are always interlaced. Blu-ray titles combine HandBrake's `InterlaceDetected` scan flag (now parsed) with an ffmpeg `idet` probe of the playlist (`bluray:` protocol); "progressive" becomes "mixed" when HandBrake saw combing. Media files are probed with ffmpeg.
  - Probes run in the background after a scan / folder listing (deduplicated, limited concurrency) and are cached in the new `InterlaceProbeCache` table (SQLite and PostgreSQL migrations) until the source changes.
  - New `Interlace` (ffmpeg path, sampling, thresholds) and `Presets` (`InterlacedPresetLabel` "4K AV1 Decomb", `ProgressivePresetLabel` "4K AV1") settings. Missing ffmpeg / libbluray falls back gracefully (HandBrake flag for Blu-ray, "unknown" for files). Docker image installs ffmpeg; see docs/configuration/interlace-detection.md for Windows.
  - MCP: `scan_disc` / `get_scan_status` titles and `list_folder_media_files` files carry `interlace`, `interlacedPercent`, `telecinePercent` and `recommendedPreset` (poll while "pending"); `queue_encode_job` accepts a per-track `presetLabel`. The server never picks a preset itself.
  - Scan page: a verdict chip and a per-track preset selector on every row, defaulting from the verdict (a changed selection is kept); the job preset applies to rows without one. Queue items keep each track's own preset.
